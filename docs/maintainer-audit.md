# 框架自体检

只在用户明确要求检查认知四象限本身，或维护者修改框架后复核时加载。检查当前有效文件，不读取或维护历史变更日志。

## 检查顺序

1. **入口一致性：** frontmatter 的触发条件、入口表、任务定向层和各模式真实职责是否一致；是否会误触发普通改写、总结、格式化或执行任务；任务定向是否被误写成第五模式。
2. **模式边界：** 扫描是否冒充百科，追问是否偷给方案，发散是否提前定案，检验是否只复述不判断。
3. **证据状态：** 是否混淆用户决定、材料声明、事实、模型知识、推断、假设和暂定选择。
4. **交接完整性：** 下游是否继承目标、约束、已排除项、用户反馈信号和证据状态；是否无理由重开已确认内容。
5. **停止条件：** 快速、标准、严格档是否可执行且不互相矛盾；是否会凑数量、过度追问或模板膨胀；每个问题和建议是否通过“不同答案/方向会改变什么”的价值门。
6. **持久化边界：** 是否获得授权、是否优先使用已有载体、是否避免敏感信息和重复文件。
7. **策略探索质量：** 用户没有方向时，是否由助手提出可评价假设；是否区分现有打法升级与新增机制；无法产生真正不同的候选时，是否指出需要补充的洞察输入，而非换词凑方案。
8. **文档一致性：** `README.md`、`CONTRIBUTING.md`、`evals/cases.md`、`SKILL.md` 与 references 是否描述同一行为；新 reference 是否有直接入口；仓库外是否出现规则副本。
9. **减法门：** 新规则替代哪条旧规则；能否删除而非追加；是否必须默认加载；没有它时模型是否真的会犯高影响错误。

## 输出

只报告会改变结论、行为、风险或维护成本的问题。每个问题说明影响、最小修复和可能回归；不自动修改文件，不在 Skill 包内追加开发历史。维护者修改框架后，必须同时检查 [evals/cases.md](../evals/cases.md) 中的相关行为案例。

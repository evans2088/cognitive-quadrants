# 框架自体检

只在用户明确要求检查认知四象限本身，或维护者修改框架后复核时加载。检查当前有效文件，不读取或维护历史变更日志。

## 检查顺序

1. **入口一致性：** frontmatter 的触发条件、入口表和各模式真实职责是否一致；是否会误触发普通改写、总结、格式化或执行任务。
2. **模式边界：** 扫描是否冒充百科，追问是否偷给方案，发散是否提前定案，检验是否只复述不判断。
3. **证据状态：** 是否混淆用户决定、材料声明、事实、模型知识、推断、假设和暂定选择。
4. **交接完整性：** 下游是否继承目标、约束、已排除项和证据状态；是否无理由重开已确认内容。
5. **停止条件：** 快速、标准、严格档是否可执行且不互相矛盾；是否会凑数量、过度追问或模板膨胀。
6. **持久化边界：** 是否获得授权、是否优先使用已有载体、是否避免敏感信息和重复文件。
7. **减法门：** 新规则替代哪条旧规则；能否删除而非追加；是否必须默认加载；没有它时模型是否真的会犯高影响错误。

## 输出

只报告会改变结论、行为、风险或维护成本的问题。每个问题说明影响、最小修复和可能回归；不自动修改文件，不在 Skill 包内追加开发历史。

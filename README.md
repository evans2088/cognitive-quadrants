# 认知四象限 / Cognitive Quadrants

> **让 AI 不急着回答，先判断你现在真正缺什么。**

我们经常带着一个还没想清楚的问题去问 AI：

- 我想做一个产品，但不知道该服务谁。
- 这个项目推进不下去，到底哪里出了问题？
- 我已经有一个方案，但总觉得还不够好。
- 几个方向都能做，我不知道该怎么选。

AI 很快就能给出用户画像、原因分析、优化建议和决策表格。答案看起来很完整，甚至比我们自己想得更周全，但聊完之后，我们仍然不知道下一步真正该做什么。

问题往往不是 AI 回答得不够好，而是它**回答得太早**。

问题还没有定义清楚，它就开始给方案；真正的原因还没有找到，它就开始提建议；可选路径还没有看全，它就开始比较优劣；关键假设还没有验证，它就开始帮你完善结论。

**认知四象限是一套让 AI 更好地与你共同思考的认知路由系统。**

它不会把所有困惑都理解成“请给我一个答案”，而是先判断：你现在究竟缺少哪一种认知，再调用最合适的思考动作。

它追求的不是让 AI 想得更多，而是让 AI 在正确的时机，做正确的思考。

## 四种不同的“没想清楚”

人们说“我还没想清楚”时，背后可能是四种完全不同的状态。

| 你当前的状态 | 真正缺少的东西 | 使用的模式 |
| --- | --- | --- |
| 你对这个领域或问题还不够了解，不知道自己漏掉了什么 | **没有看见的关键问题** | **盲区扫描** |
| 你隐约有一个想法，但目标、对象、概念或约束还很模糊 | **清楚的问题定义** | **追问者** |
| 问题已经比较清楚，但担心只看见了自己熟悉的几条路 | **足够完整的选择空间** | **发散者** |
| 已经有了方案或判断，但不知道它是否真的成立 | **经过检验的结论** | **检验者** |

这四种状态看起来相似，处理方式却完全不同。

从结构上看，四个模式来自两条轴：你在处理的是**问题**还是**方案**；此刻需要的是**展开**认知，还是**收敛**认知。

|  | 展开认知：补全还没看见的部分 | 收敛认知：形成更清楚的判断 |
| --- | --- | --- |
| **处理问题** | **盲区扫描**<br>还有什么关键问题没有看见？ | **追问者**<br>真正的问题、目标和约束是什么？ |
| **处理方案** | **发散者**<br>除了眼前这条路，还有哪些不同可能？ | **检验者**<br>这个方案的假设、证据和风险站得住吗？ |

不知道自己遗漏了什么，却不断追问细节，可能只会在错误的方向上越想越深；问题还没定义清楚，就开始发散方案，会得到大量无法比较的选项；选择范围本来就不完整，过早做决策分析，只会在几个有限选项中精确地选错。

所以，认知四象限首先做的不是回答，而是**分辨你现在面对的是哪一种未知**。

## 同一个问题，可能需要完全不同的处理

例如，你说：

> “我想做一个 AI 产品，但不知道应该服务谁。”

这句话背后可能有四种不同情况。

如果你刚接触这个领域，连不同用户为什么需要 AI、目前有哪些替代方案都不清楚，你需要的是**盲区扫描**。

如果你只是有一个模糊的产品念头，连具体解决什么场景、创造什么价值都说不清楚，你需要的是**追问者**。

如果产品解决的问题已经明确，只是担心自己想到的用户范围太窄，你需要的是**发散者**。

如果你已经在独立创作者和小型团队之间犹豫，需要判断哪个方向更值得投入，你需要的是**检验者**。

表面上是同一个问题，真正缺少的认知完全不同。固定提示词通常只能规定 AI“怎么回答”，认知四象限则先判断**此刻是否应该这样回答**。

## 它真正改变了什么

认知四象限不是把四个 Prompt 串成流水线，而是一套约束 AI 如何参与思考的协作机制。它会围绕本轮问题维护：什么已经确定、什么仍是未知、哪些是事实或假设；只有你决定切换时，才把必要上下文带到下一个模式。

### 1. 从“生成答案”转向“缩小未知”

一轮对话是否有效，不看 AI 输出了多少内容，而看它是否减少了一个真正影响判断的未知。

可能是发现了此前没有意识到的关键变量，可能是把模糊目标说清楚，可能是增加了一个真正不同的选项，也可能是暴露了一个足以推翻方案的假设。

如果只是复述、分类、扩写或把你的原话整理成表格，即使形式很完整，也不算真正推进了问题。

### 2. 一次只做当前最需要的一步

认知四象限不会机械地把所有问题都跑一遍“扫描—追问—发散—检验”。

它会先选择当前最匹配的一个模式，只处理最有可能改变理解和行动的部分。如果你决定切换，再把已有结论、尚未解决的问题和新增信息一起带到下一个模式。

这样既避免简单问题被过度分析，也避免复杂问题在一轮对话里同时发散、判断和给方案，最后越聊越乱。

对于“我还没有方向，希望你带我一起想”的复杂策略问题，系统会先做一层**任务定向**：判断是澄清用户已有想法、由 AI 主导生成方向、检验已有方案，还是在有限候选中做取舍。任务定向不是第五种模式，也不会要求用户先提供一套候选答案；它只决定四个模式接下来如何协作。

这类任务会把“现有做法如何升级”和“是否需要新增机制”分开处理。只有改变了问题所处的机制或关键行为，才算新增方向；把既有渠道、内容或执行动作重新组合，只标为现有打法升级。

### 3. 区分事实、假设与偏好

很多错误判断并不是因为没有逻辑，而是把“我听说”“我感觉”“行业通常如此”和已经验证的事实混在了一起。

用户的价值选择、风险取舍和具体情境经验会被认真继承；当结论依赖一般事实、外部状态或普遍因果时，认知四象限会区分材料声明、事实、推断和假设，并根据任务风险决定需要多严格的证据。

它不是为了让所有问题都变得复杂，而是避免一个未经验证的前提，被 AI 包装成看似可靠的完整结论。

### 4. 保留人的判断权

AI 可以帮助你看见、澄清、扩展和检验，但不会把你的偏好伪装成事实，也不会因为输出了一份完整方案，就假装决定已经完成。

认知四象限的目标不是替你思考，而是帮助你更清楚地知道：

- 现在已经确定了什么；
- 还有什么没有确定；
- 哪个未知最值得优先处理；
- 下一步做什么最有信息价值。

## 四个模式分别做什么

### 盲区扫描

适合你对一个领域、现象或问题还不够熟悉，不知道自己遗漏了什么，或者只看见了表面症状，却不知道可能的原因。

它会帮助你发现关键变量、常见失败模式、潜在约束和需要验证的解释，而不是立刻给出一个确定原因。

```text
帮我扫描盲区：我想做一个面向独立创作者的知识库产品。
```

### 追问者

适合你已经有一个想法或困惑，但目标、对象、概念、边界或成功标准还说不清楚。

它不会把所有问题一次问完，而是从最可能改变方向的问题开始，逐步把模糊想法收成一个可以讨论、验证或执行的问题。

```text
帮我追问一下：我想做一个 AI 产品，但还没想清楚要服务谁。
```

### 发散者

适合问题已经比较明确，但你担心当前的思路受到经验、惯性或现有方案限制。

它会从不同机制、视角和路径扩展真正不同的选择，不急着替你筛选，也不会为了数量制造大量相似方案。

```text
帮我发散一下：我们已经确定要提高新用户激活率，还有哪些不同路径？
```

### 检验者

适合你已经有方案、判断或表达，希望知道它是否站得住，哪里可能被质疑，什么证据还不够。

它会区分事实、推断和假设，寻找反例、风险和证据缺口；需要时，也可以模拟老板、客户、投资人或其他关键角色进行压力测试，并把结果收成可使用的方案或表达。

角色模拟、AI 内部审查和多 Agent 互评只能暴露逻辑风险与证据缺口，不等于真实用户反馈、业务数据或现实验证。重要判断仍需要权威资料、真实行为、可复现工具结果或实际实验来支持。

```text
帮我检验这个方案：先用低价获客，再靠高级版本回本。请模拟老板追问。
```

## 一次使用后的状态变化

用户说：

> “过去两周，我的课程转化率从 8% 降到 3%。帮我找根因。”

如果 AI 立刻断言“内容不够好”或“流量质量下降”，那只是把猜测包装成原因。认知四象限会先进入盲区扫描：锁定症状和基线，列出彼此可区分的解释，并标出每种解释需要什么数据或最低成本动作来验证。

这轮结束时，用户得到的不是一份冗长的原因清单，而是一张可行动的地图：**目前有哪些解释、先查什么、什么结果会支持或推翻哪种解释。** 下一步才可能进入检验、方案设计或其他模式。

## 最简单的使用方式

你不需要先学习这套框架，也不需要自己判断该进入哪个模式。

直接说：

```text
使用认知四象限处理下面的问题，并直接开始：

……
```

AI 会判断当前最匹配的模式，简要说明原因和处理深度，然后直接开始。它默认只运行一个模式，不会未经需要自动走完整流程。

如果你只想获得建议，暂时不展开：

```text
判断下面的问题适合使用哪个认知四象限模式，并说明原因，先不要开始：

……
```

如果你已经知道自己需要什么，也可以直接说“扫描盲区”“追问一下”“发散一下”“检验一下”或“模拟老板追问”。

如果你还没有成熟方向，可以直接说：

```text
使用认知四象限处理这个问题。我还没有答案，请先帮我形成几个可讨论的方向，不要先让我提供候选方案：

……
```

AI 会只补充会改变方向的必要信息，再提出可评价的假设；当你说“没价值”“这不是本轮要讨论的内容”或“所以呢”时，后续处理应随之改变，而不是继续堆叠同一层级的内容。

## 什么时候适合使用

认知四象限适合那些不能靠一次查询或一次生成解决的问题，例如：

- 产品、项目和商业判断；
- 职业选择与重要决策；
- 复杂问题的原因诊断；
- 模糊想法的澄清与定义；
- 方案设计和路径扩展；
- 重要方案、汇报和沟通前的压力测试；
- 多条主线互相影响、需要持续推进的问题。

它不适合纯改写、翻译、格式整理、明确规格下的执行任务，或只需查询一个确定事实的问题。

医疗、法律、财务和合规等高风险议题，可以使用它辅助厘清问题和检查假设，但不能替代权威资料和专业人士的判断。

## 复杂问题与复盘

如果一个问题跨度很长、涉及多条主线，一轮对话无法处理完，可以说：

```text
帮我认知寻路：……
```

它会先在当前对话中建立问题地图，区分当前目标、已经确定的内容、仍有认知雾区的部分和暂时不处理的范围；仅说“认知寻路”不会自动创建文件。

如果需要跨会话持续更新，可以明确说：

```text
帮我建立一份跨会话认知地图，并保存到这个项目里：……
```

一轮结束后，如果希望整理这次真正学到的经验，可以说：

```text
帮我复盘这一轮。
```

这会先在对话中输出复盘记录，不会自动写入文件。如果希望保存，明确说：

```text
帮我复盘这一轮，并把复盘记到项目笔记里。
```

持久化时会优先更新已有载体，避免重复创建笔记。

认知寻路和复盘者是辅助工具，不是额外的两个象限。

## 安装

本项目遵循 [Agent Skills](https://agentskills.io/specification) 的目录约定。发布到 GitHub 后，在支持 [skills.sh](https://skills.sh/) 的环境中运行：

```bash
npx skills@latest add evans2088/cognitive-quadrants
```

也可以将 [`skills/cognitive-quadrants/`](skills/cognitive-quadrants/) 整个目录复制到目标 Agent 的 skills 目录。

不同客户端的自动发现方式、安装位置和命令可能不同。没有 skill 命令时，也可以在对话中明确说：

```text
使用 cognitive-quadrants 处理下面的问题：……
```

核心 skill 不依赖专属工具或凭据；没有网络时仍可澄清问题、整理假设和设计验证，但不会把无法核验的外部事实当成已确认结论。更多信息见 [兼容性说明](docs/compatibility.md)。

# 认知寻路（Wayfinding）

**什么时候用：** 一个想法或材料大到一轮会话装不下，关键决定彼此依赖，当前还无法直接形成完整方案。

**典型触发语：**「帮我认知寻路」「这个问题太大了，帮我分几轮想清楚」「先给这个项目建张认知地图」

认知寻路是可选的跨会话基础设施，不是第五象限。用户明确要跨会话推进或建立认知地图时，它负责维护持久地图；只想当前会话拆解时，地图留在对话中并明确未持久化。具体问题再按需调用扫、问、散、验。

## 核心概念

- **目的地**：走到什么状态算这轮大问题已经想清楚。它固定范围，不等于立刻实施。
- **当前前沿**：现在已经能准确表达、可以直接处理的问题。
- **阻塞问题**：问题已清楚，但必须等待其他问题先解决。
- **认知雾区**：知道未来需要处理，但目前还无法提出准确问题。**判断标准**：如果你现在能精确表述这个问题（即使还没法回答它），它就不是雾区，而是一个待办问题；如果你连问题本身都还没法精确说出来，它属于雾区。雾区不预先切成问题大小的块——一块雾可能变成多个问题，也可能一个都不变。
- **范围外**：明确不属于本轮目的地；除非目的地改变，否则不再返回。
- **已确认认知**：已经解决的用户主权选择、带边界的局部经验、已验证事实或暂定选择；保留类型、来源、适用边界和重新打开条件。

## 大墙分类（卡住时按需使用）

长链路任务里“卡住”的本质和小场景不同——往往是跨子问题的**结构关系**，不是单个问不出来的点。本分类只在大场景里用；小卡点仍走[追问者](probing.md)的 5 类（假设/框架/守门人/资源/问题），不混用。

**使用纪律：遇到已经能准确表达的阻塞问题时，先判墙类型，再选推进动作。真正的认知雾区先保持为雾区，不强行判墙；只挑最上游 1-3 类，不逐项覆盖。分类是定位撬棍的工具，不是每次必走的清单。**

| 墙类型 | 大场景里“卡住”意味着 | 优先处置动作 |
|---|---|---|
| 依赖墙 | 这题的答案依赖另一题先解，另一题还没动 | 先解锁上游；或给暂定假设向前推进（标重新打开条件） |
| 组织/守门人墙 | 卡在跨部门/跨角色、谁拍板谁执行不清 | 定位否决权归属、明确决策权、找替代路径 |
| 架构墙 | 受系统/数据/平台硬结构限制，改不了 | 在约束内找可行解；或把约束本身列为待改前提 |
| 信息墙 | 关键事实缺口且短期拿不到（不采集/无人知） | 标证据缺口+最小采集动作；先按推断推进并标状态 |
| 假设墙 | 继承来的、没人复验的信念在承重 | 列信念→事实/推断→拆前提 |
| 框架墙 | 问题被表述成排除了答案的样子 | 升维（服务的最终目标）/降维（具体哪步卡） |
| 资源墙 | 缺时间/钱/人/权限 | 最小可行版、借力已有、先降范围 |
| 问题墙 | 把实践性问题（Problem）当问答（Question）带了 | 建议扫描/寻路，不自动切换或硬问答 |
| 定义墙 | 核心概念歧义，下游各说各话 | 先对齐关键定义再展开（追问者承重概念） |
| 范围墙 | 目的地太大/漂移，子问题全膨胀 | 收紧目的地、重划范围外、拆成独立子目的地 |
| 优先级墙 | 多个都能解但排不出序、互相抢注意力 | 按信息增益/解锁数排序；若仍无法排序，可先做一次最低成本的优先级判别试探，只收集区分优先级所需的信息，然后仍只推进一个高影响前沿 |
| 动力墙 | 知道怎么做但跨会话断了/拖延 | 缩小下一轮入口、锁定最小可完成单元 |

## 地图载体

- 已有用户指定的项目约定或地图文件，且本轮内容确需续接时，沿用原位置并原地更新，不创建平行副本；只有当前会话拆解且不需续接时才不写入。
- 有可写工作区但没有约定时，只有用户明确要建立跨会话地图才保存为 `认知地图-<主题>.md`，并在回复中给出路径；否则在对话中输出临时地图并注明未持久化。
- 没有可写位置时，输出完整地图并明确“当前未持久化”；请用户指定保存位置后再称为跨会话地图。
- 每次更新写明更新时间和下一轮入口。新会话先读地图，不重读全部旧对话。

## 建图

1. 读取 [追问者](probing.md)，先明确目的地、不可改变前提和范围外。
2. 广度扫描问题空间，不立即深挖一个分支。
3. 能准确表达的问题进入当前前沿或阻塞问题；说不清的保留在认知雾区。
4. 为每个已经能准确表达的当前问题标记处置动作：查证、追问、样例/原型、现实验证或解锁任务，并写明**解决／更新信号**：出现什么新事实、用户决定或反馈后，它能离开当前前沿，或应怎样更新地图。**标动作前先判它属于哪类墙**（见上方大墙分类）——墙类型决定动作，不默认盲选；认知雾区先保留，不强行判墙或分配具体动作。一次动作若只能降低不确定性，就记录它会更新什么判断，不强行把节点写成已解决。涉及研究、样例或现实验证时，没有可靠基准不得在地图中编造样本量、周期或阈值；说明这些参数应由什么历史数据、风险承受度或现实约束决定。
5. 如果没有认知雾区且当前前沿都能一轮处理完，停止建图，建议用户按当前问题选择普通四象限模式，不自动开始。

## 逐轮推进

每轮只解决一个高影响前沿问题：

1. 先读取地图的低分辨率全貌，不展开所有旧材料。
2. 优先处理会解锁最多后续问题的节点。
3. 根据问题类型选择动作：事实缺口走 [证据协议](evidence-protocol.md)；领域盲区读 [盲区扫描](blindspot-scan.md)；用户主权选择或局部经验提取读 [追问者](probing.md)；需要扩展读 [发散者](challenging.md)；需要收敛读 [检验者](validation.md)。每轮只加载当前需要的一个模式。
   - **推进前先判墙：** 若某个已经能表达的前沿或阻塞问题卡住不动，先用大墙分类定位它属于哪类墙，再选动作——例如依赖墙先解锁上游、组织墙先定否决权、信息墙先标缺口。不绕圈硬推；真正的认知雾区不强行分类。
4. 记录结论的类型、来源、适用边界、仍未验证之处和重新打开条件；局部经验不冒充普遍事实。
5. 更新前沿、阻塞关系、雾区与范围外。
6. 更新产物累积清单：记录本轮新增的结论/风险/假设/改动，标记落盘状态。未落盘产物仅保留状态记录；只有用户要求保存，或它是下一轮不可缺的依据时才处理。是否写入仍遵守按需持久化规则，不因清单自动创建文件。
7. 通过 [交接契约](handoff-contract.md) 留下下一轮入口。

```markdown
# 认知地图：<主题>

**更新时间：** <YYYY-MM-DD HH:MM>

## 目的地
<一两句话说明走到哪里算想清楚>

## 不可改变前提
- ...

## 已确认认知
| 类型 | 内容 | 来源/理由 | 适用边界 | 重新打开条件 |
|---|---|---|---|---|
| 用户主权选择/局部经验/已验证事实/暂定选择 | ... | ... | ... | ... |

## 产物累积
| 产物 | 性质 | 落盘状态 | 路径/位置 |
|---|---|---|---|
| 已确认结论 / 已承认风险 / 待验证假设 / 改动清单 | ... | 已落盘 / 未落盘 | ... |

## 当前前沿
| 问题 | 处置动作 | 解决／更新信号 | 解锁什么 |
|---|---|---|---|
| ... | 查证/追问/样例/验证/解锁 | ... | ... |

## 阻塞问题
| 问题 | 被什么阻塞 | 墙类型 |
|---|---|---|
| ... | ... | 依赖/组织/架构/信息/…（按需标注） |

## 认知雾区
- <知道这块将来要处理，但还无法准确提问>

## 范围外
- <本轮明确不处理的内容及原因>

## 下一轮入口
<下一步只处理什么，为什么它信息增益最高>
```

# 检验者（Validate / Converge）

## 目录

- 作用与边界
- 选择深度
- 六个审查维度
- 执行
- 停止条件
- 参考输出

**什么时候用：** 已有一个或多个方向，需要判断是否值得做、哪个更成立、如何融合，以及哪里会失败；也用于用相关方视角演练重要方案或沟通。

**典型触发语：**「帮我收一下」「帮我检验一下」「哪个更靠谱」「所以到底怎么做」「模拟老板追问」「演练一下这个汇报」

## 作用与边界

检验者不是给方案打分，而是检查六类可能导致判断失真的问题：方向是否偏了、推理是否缺环节、依据是否可靠、是否具备执行条件、失败时是否可接受，以及相较其他选择是否值得。最终交付的不只是“好不好”，还要说明结论在什么条件下成立、哪些地方仍待验证，以及它如何改变下一步行动。

- 可以给出明确判断，但要说明依据、取舍、放弃了什么和不确定性。
- 只做与当前决定相关的检查，不重新完整发散；需要补选项时建议改用发散者，不自动切换。
- 继承已确认的目标与边界；出现矛盾、新证据或关键风险时，按 [交接契约](handoff-contract.md) 标为待重新确认。
- 按 [证据协议](evidence-protocol.md) 区分用户主权选择、局部经验、已验证事实、材料声明、模型知识、推断和待验证假设。
- 证据不足只限制现实结论的强度，不能替代推理；仍要提炼现有前提能够支持的结构性结论、决策后果和下一步验证。
- AI 的逻辑审查、角色演练、对抗性批评或多个 Agent 互评只属于内部推演，用于暴露理解偏差、异议和证据缺口；它们不等于真实相关方、外部证据或现实结果。

## 选择深度

- **标准档：** 默认质量底线。先检查是否存在会改变结论、带来重大风险或构成阻断的因素，再深入处理与本轮决定相关的维度；区分事实、推断和待验证内容，说明结论边界与下一步。可以只展示最相关的维度，但不得把未展示的维度默认视为成立。
- **严格档：** 高成本、长期、外部发布、影响多人、高风险领域，或用户要求“深挖/严格检验”时使用。在标准档基础上，检查全部相关维度，增加独立查证、主要反例、失败条件和敏感性检查。

“简洁”或“完整”只描述输出方式，不降低标准档的质量要求。若一个未展示的维度可能带来重大风险、构成阻断或改变结论，必须纳入本轮；否则应明确说明它不在本轮范围内。
用户要求尽快、简单看或先粗看时，仍按标准档处理；可以压缩呈现，但不能省略会改变结论、带来重大风险或构成阻断的必要检查。

## 六个审查维度

六个维度不是打分表，而是检查结论是否可能出错的六个方面：

| 审查维度 | 核心问题 | 这一维度的价值 |
|---|---|---|
| **问题与目标** | 方案解决的是否是真正的问题？预期结果是否明确？ | 防止方向偏移，避免解决表面问题却没有推动真实目标 |
| **推理链条** | 从现有条件到预期结果，中间是否缺少关键环节？ | 检查结论是否由前提支持，避免把愿望、相关性或类比当成因果 |
| **事实与依据** | 影响结论的关键信息是否有可靠、相关且及时的依据？ | 区分事实、经验、推断和假设，避免建立在错误或过时信息上 |
| **执行条件** | 资源、能力、时间、权限、时机和相关方是否支持执行？ | 判断能否落地，并收缩出当前真正可执行的范围 |
| **风险与边界** | 出现例外、变化或失败时，方案是否仍然可接受？ | 暴露适用边界、失败路径和不可接受后果，确定保护措施与停止条件 |
| **取舍与优先级** | 相比不做或其他选择，当前投入是否值得？ | 综合收益、成本、机会代价和可逆性，确定优先级与下一步 |

任何一项出现足以阻断行动的严重问题，都不能用其他维度的优点抵消；它必须单独影响总体结论。

## 执行

**检验用户已有方向时：先逐条压力测试，不默认收拢成一个大方案。** 对每条方向至少判断：它在组合中的角色、它实际换来的结果、关键前提、最可能失效处、可行的升级方式，以及在什么条件下应停止投入。只有用户明确要求融合，或检验显示多条方向确实解决同一缺口时，才提出主—吸收方案。用户要求新增方向时，先与“现有打法升级”分开呈现；新增候选不足时说明当前检验的限制，可以建议改用 [策略探索](strategy-exploration.md) 补洞察输入，但不自动切换或用概念包装硬凑。

**从发散进入检验时：** 只接收用户选中或明确提升的少量候选，并按 [交接契约](handoff-contract.md) 保留轻量假设卡。不要回头要求所有发散候选补齐实验设计，也不要把假设卡字段机械展示为固定模板。

**可选基线：记录初始直觉（gut call）。** 锁定检验对象后，如果用户已经主动表达一句话的直觉判断（“你一上来觉得哪个更靠谱 / 这事大概率成不成”），先把它记为基准。目的不是服从直觉，而是防止后续“分析”只是给直觉找理由；用户没有主动表达时不额外追问。

1. **锁定检验对象。** 区分材料载体、材料内容和真正决策对象；用一句话说明“本轮检验 X，不检验 Y”。列出候选、目标、成功标准、关键约束、明确不做和范围外，保持候选原意；用户反馈已排除的路径不得重新引入。
2. **建立已知与已定。** 主动回读当前对话和相关材料，单独列出用户已经知道、已经决定和已经排除的内容，同时区分助手提出、暂定采用和待验证的内容。完整性检查由检验者承担，不把“有没有遗漏、哪些是共识”交回用户；这些内容可作为前提，但改写、分类或加表格后仍不算本轮新增判断。
3. **识别关键前提。** 找出最多 3–5 个“一旦不成立，就会改变当前结论、优先级或行动方向”的前提，先确定其依据状态。
4. **选择深度与维度。** 标准档先检查是否存在遗漏的重大风险或阻断，再选择与本轮决定最相关的维度；严格档检查全部相关维度，并补做独立查证、反例和敏感性检查。
5. **对比或融合。** 形成优选、融合或主—吸收方案，说明理由、关键取舍和放弃内容。多方案对比时，比较各方案的可逆性（最小承诺获得的信息量、回滚成本）；天然不可逆的决定标为不适用。每个方案列出长期代价（复杂度、维护和认知成本），每方案最多 3 条、每条一句话；单方案时将当前方案与“不做”对比。
6. **对抗审查。** 检查核心假设为假、边界情况、反例、同源依据和失败条件。发现关键问题时回退，并说明新判断推翻了什么。
   - 严格档改变 1–2 个合理但不确定的关键前提，观察推荐是否变化，并标为**稳定 / 混合 / 不稳定**。
   - 若记录过初始直觉，且最终方向改变，必须说明是哪条新依据或哪个前提推翻了它。
   - 角色演练仅在用户明确要求时使用；先锁定角色、场景、已知事实和真实利益/权限，一次只提出一个最有压力的追问。模拟反应只能标为“待真实反馈验证”。
7. **形成新增判断。** 对照“已知与已定”，至少形成一种会影响理解或行动的变化：拆开混在一起的概念、暴露关键依赖、改变优先级或取舍、推出新的决策后果，或给出明确推翻条件。若没有，直接说明本轮没有新增判断，不用结构化复述填满输出。
8. **标注依据状态与决策影响。**
   - **依据状态：** 已确认 / 部分支持 / 待验证 / 存在冲突。
   - **决策影响：** 可以继续 / 需要调整 / 暂缓推进 / 构成阻断 / 不适用。
   - 不能用“证据不足”代替“暂缓推进”，也不能用“构成阻断”代替证据判断；两者分别回答“知道多少”和“现在能否行动”。
9. **设计下一步验证。** 对影响最大的待验证问题，说明验证什么、采取什么动作、观察什么信号，以及什么结果会改变当前判断。没有可靠基准时，不擅自编造测试预算、样本量、比例、周期、阈值或止损线；说明这些数应由什么历史数据、单位经济模型、风险承受度或现实约束决定。
10. **交付收口。** 结论先于过程，先说明总体判断和对行动的影响，再提供相关维度的依据。根据用户需要转成方案、汇报或行动版；确认门只用于即将实施高成本、外部可见或改变目标的动作。

## 停止条件

- 已锁定真正的检验对象，没有把材料载体误当成决策对象，也没有偷换问题或候选含义。
- 已区分用户原有认知与本轮新增判断；至少一个判断改变了理解或行动，否则已明确说明没有新增判断。
- 没有把用户原话的改写、分类、表格化或依据状态标注冒充检验成果。
- 所选维度都已说明主要发现、依据状态和决策影响；未纳入的维度已标为本轮范围外，且不存在未检查的重大风险或阻断。
- 每个关键前提都已标注依据状态，整体结论状态已确定：可执行结论 / 条件性判断 / 暂时无法判断 / 本轮没有新增判断。
- 严格档已说明结论稳定性；不稳定时没有强行拍板。
- 使用角色演练时，已说明它暴露的沟通或依据缺口，不将模拟反应当作真实相关方立场。
- 没有把 AI 内部审查、多个 Agent 的一致意见或角色模拟称为现实验证。
- 最重要的待验证问题有明确的下一步验证。
- 输出深度与任务风险匹配，结论先于分析。

## 参考输出

简单问题只输出总体判断、行动影响和下一步验证；标准档复杂任务可增加相关维度表；严格档增加完整维度表、关键前提、敏感性和完整依据说明。

```markdown
## 检验结论

**总体判断：** ...
**对行动的影响：** ...

### 审查依据

| 审查维度 | 主要发现 | 依据状态 | 决策影响 |
|---|---|---|---|
| 问题与目标 | ... | 已确认/部分支持/待验证/存在冲突 | 可以继续/需要调整/暂缓推进/构成阻断/不适用 |

### 关键前提

- ...

### 尚待验证

| 问题 | 下一步验证 | 什么结果会改变判断 |
|---|---|---|
| ... | ... | ... |

### 下一步

...
```

## 参考输出分模板

根据用户任务类型选择输出模板：

- **对话模板（默认）：** 先交付总体判断，不展示与行动无关的检查过程。
- **完整分析模板：** 用于严格检验、重要决策审计或用户明确要求报告时，增加完整维度表、关键前提、敏感性和依据说明。
- **交付模板：** 用户说“所以呢”“直接告诉我怎么改”“拿去执行”或“拿去汇报”时，输出改动清单、待办表或结论卡，直接对应用户要交付的成果。

停止时执行**产物价值门与锚定**；持久化遵守 `SKILL.md` 的按需持久化规则。

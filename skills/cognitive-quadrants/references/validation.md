# 检验者（Validate / Converge）

## 目录

- 行为边界
- 选择深度
- 执行
- 停止条件
- 参考输出

**什么时候用：** 已有一个或多个方向，需要判断是否值得做、哪个更成立、如何融合，以及哪里会失败；也用于用相关方视角演练重要方案或沟通。

**典型触发语：**「帮我收一下」「帮我检验一下」「哪个更靠谱」「所以到底怎么做」「模拟老板追问」「演练一下这个汇报」

## 行为边界

- 可以给明确判断，但要说明依据、放弃了什么和不确定性。
- 只做轻量查遗，不重新完整发散。
- 继承已确认的目标与边界；出现矛盾、新证据或致命问题时，按 [交接契约](handoff-contract.md) 标为待重新确认。
- 按 [证据协议](evidence-protocol.md) 区分用户主权选择、局部经验、事实、材料声明、模型知识、推断和假设。
- 真实任务要收成可用交付，但证据不足时不能用完整方案伪装可靠结论。
- 证据不足只限制现实结论的强度，不能替代推理。仍要提炼现有前提能够支持的结构性结论、决策后果和最有信息价值的验证动作。
- AI 的逻辑审查、角色演练、对抗性批评或多个 Agent 互评只属于内部推演，用于暴露理解偏差、异议和证据缺口；它们不等于真实相关方、外部证据或现实结果，不能自行完成验证。

## 选择深度

- **快速检验：** 低风险、可逆或用户只要参考意见。只检查最可能改变结论的 1-2 个轴，直接给条件明确的 go/no-go 或优先方向。未选审查轴不作结论；只有在已确认任务低风险且可逆时，才将其视为本轮范围外。若任一未选轴可能涉及不可逆、外部可见或高成本风险，自动升标准档，或请用户显式确认承担未查轴风险后再给结论。
- **标准检验：** 默认。选择 3-4 个最相关审查轴。
- **严格检验：** 高成本、长期、外部发布、影响多人、高风险领域或用户要求深挖。完整检查相关六轴，做对抗审查和敏感性检查。

六个审查轴是参考库，不是每次必填：

| 审查轴 | 核心问题 |
|---|---|
| 目标一致性 | 它解决的是用户真正的问题吗？ |
| 逻辑完整性 | 结论是否超出前提？ |
| 事实可信度 | 承重前提是否有独立、相关、可靠的证据？ |
| 现实可行性 | 时间、资源、能力、时机和相关方是否允许？ |
| 鲁棒性 | 反例、边界和失败场景下是否成立？ |
| 决策质量 | 得到什么、放弃什么，是否值得？ |

任何相关轴出现致命问题，都不能被其他轴的优势平均掉。

## 执行

**检验用户已有方向时：先逐条压力测试，不默认收拢成一个大方案。** 对每条方向至少判断：它在组合中的角色、它实际换来的结果、承重假设、最可能失效处、可行的升级方式，以及在什么条件下应停止投入。只有用户明确要求融合，或检验显示多条方向确实解决同一缺口时，才提出主—吸收方案。用户要求新增方向时，先与“现有打法升级”分开呈现；新增候选不足时说明当前检验的限制，可以建议改用 [策略探索](strategy-exploration.md) 补洞察输入，但不自动切换或用概念包装硬凑。

**从发散进入检验时：** 只接收用户选中或明确提升的少量候选，并按 [交接契约](handoff-contract.md) 保留轻量假设卡。不要回头要求所有发散候选补齐实验设计，也不要把假设卡字段机械展示为固定模板。

**可选基线：记录初始直觉（gut call）。** 锁定检验对象后，如果用户已经主动表达一句话的直觉判断（“你一上来觉得哪个更靠谱 / 这事大概率成不成”），先把它记为基准。目的不是服从直觉，而是防止后续“分析”只是给直觉找理由；用户没有主动表达时不额外追问。

1. **锁定检验对象。** 区分材料载体、材料内容和真正决策对象；用一句话说明“本轮检验 X，不检验 Y”。列出候选、目标、成功标准、关键约束、明确不做和范围外，保持候选原意；用户反馈已排除的路径不得重新引入。
2. **建立认知基线。** 单独列出用户已经知道、已经决定和已经排除的内容。它们可作为前提，但改写、分类或加表格后仍不算本轮新增结论。
3. **扫描承重前提。** 找出最多 3-5 个“错误就会改变结论”的声明，先确定证据状态。
4. **选择深度与审查轴。** 按风险决定快速、标准或严格，不机械跑满六轴。
5. **对比或融合。** 形成优选、融合或主—吸收方案，说明理由、关键取舍和放弃内容。多方案对比时，比较各方案的可逆性（最小承诺获得信息量、回滚成本），天然不可逆决策标为维度不适用。每个方案列出长期代价（复杂度税、维护税、认知税），每方案最多 3 条、每条一句话；单方案时将当前方案与"不做"对比代价。
6. **对抗审查。** 检查核心假设为假、边界情况、反例、同源证据和失效条件。发现致命问题则回退并说明新版本推翻了什么。
   - 严格档改变 1-2 个合理但不确定的承重前提，观察推荐是否变化，并标为**稳定 / 混合 / 不稳定**。
   - **直觉对照：** 若记录的初始直觉与最终结论方向相反，必须在结论中显式交代“为什么变了”——是哪些新证据或承重前提推翻了直觉，而不是把直觉悄悄覆盖。
   - **角色演练（按需）：** 用户明确要求时，先锁定角色、场景、已知事实和该角色的真实利益/权限；一次只提出一个最有压力的追问。每轮指出回答中模糊、回避或缺乏证据之处，并把演练得出的判断标为“待真实反馈验证”。若当前最大未知是某个相关方会如何理解、质疑或否决，但用户未要求演练，只建议这一验证方式，不自动开始。
7. **形成认知增量。** 对照认知基线，至少形成一种会影响理解或行动的变化：拆开被混在一起的概念、暴露隐藏依赖、改变优先级或取舍、推出新的决策后果、给出明确推翻条件。若没有，直接说明本轮没有新增结论，不用结构化复述填满输出。
8. **确定结论状态。**
   - **可执行结论：** 承重前提足够可信，可进入行动。
   - **条件性判断：** 只能说明“若 A 成立，则逻辑上可行”，不得包装成现实结论。
   - **暂时无法判断：** 承重前提普遍未验证或互相冲突；只输出证据缺口和验证动作。
9. **设计最小证据切片。** 对影响最大的未验证假设，说明验证动作、观察信号和推翻条件。
   - 先按 [证据协议](evidence-protocol.md) 说明当前能得到的是内部推演、外部证据还是直接现实观察，不用多个 AI 的一致意见冒充独立现实证据。
   - 需要现实验证时，按任务需要补充反馈来源、行动者和结果要更新的原假设；只有涉及外部协作、高成本或授权边界时才显式说明决定权。
   - 当两个选项接近、结论不稳定或证据普遍较弱时，优先推荐信息价值最高的低成本验证，不强行选择。
   - 没有可靠基准时，不擅自编造测试预算、样本量、比例、周期、阈值或止损线。说明这些数应由什么历史数据、单位经济模型、风险承受度或现实约束决定；必要时给计算式、待确认字段或保守的分阶段原则，而不填伪精确数字。
10. **交付收口。** 快速档建议优先给出 3-4 个最有影响的新增结论，但不设硬性条数；不足时不凑数，确有更多独立且会影响理解或行动的结论时也不强删。标准档不设硬性数量上限，按改变决策的影响排序、合并重复结论，只保留仍然独立且会改变理解或行动的内容。其余检查过程不展开，除非它会推翻结论。再说明这些结论改变了什么、依据和边界、最小验证动作。根据用户需要转成方案、汇报或行动版；确认门只用于即将实施高成本、外部可见或改变目标的动作。

## 停止条件

- 已锁定真正的检验对象，没有把材料载体误当成决策对象，也没有偷换问题或候选含义。
- 已区分用户原有认知与本轮新增结论；至少一个结论改变了理解或行动，否则已明确说明没有新增结论。
- 没有把用户原话的改写、分类、表格化或证据状态标注冒充检验成果。
- 所选审查轴的每个轴都已给出明确结论（通过/不通过/有条件通过），致命问题已回退或阻断。
- 每个承重前提都已标注证据状态，结论状态已确定（可执行/条件性/暂时无法判断）。
- 严格档已说明结论稳定性；不稳定时没有强行拍板。
- 使用角色演练时，已说明它暴露的沟通或证据缺口，不将模拟反应当作真实相关方立场。
- 没有把 AI 内部审查、多个 Agent 的一致意见或角色模拟称为现实验证。
- 最重要的未验证假设有最小证据切片。
- 输出深度与任务风险匹配。
- 快速档建议参考 3-4 个新增结论，但不设硬性条数；不足时不凑数，确有更多独立且影响决策的结论时不强删。标准档没有硬性数量上限，但已合并重复内容，并只保留独立且影响决策的结论。

## 参考输出

快速和标准检验默认使用简洁的认知增量格式：

```markdown
## 检验结论

**检验对象：** 本轮检验...，不检验...
**结论状态：** 可执行 / 条件性 / 暂时无法判断 / 没有新增结论

### 新增结论
1. ...
2. ...

### 改变了什么
- 原来：...
- 现在：...

### 依据与边界
- ...

### 最小证据切片
- **验证：** ...
- **动作：** ...
- **观察信号：** ...
- **推翻条件：** ...

### 下一步
...
```

## 参考输出分模板

根据用户任务类型选择输出模板：

- **对话模板（默认）：** 使用上方简洁格式，先交付新增结论，不展示全量检查过程。
- **完整分析模板：** 仅用于严格检验、重要决策审计或用户明确要求报告时，增加审查轴表、承重前提表、敏感性和完整证据切片。
- **交付模板**（文档收口类问题：原文档要改哪几处？结论能不能写进去？）：输出改动清单 / 待办表 / 结论卡，直接对应"用户要改的东西"，不堆分析过程。

用户任务类型不明显时，默认用对话模板；用户说"所以呢""直接告诉我怎么改""拿去执行"时，切交付模板。

停止时执行**产物价值门与锚定**；持久化遵守 SKILL.md 的**按需持久化**规则。

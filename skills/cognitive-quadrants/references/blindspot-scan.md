# 盲区扫描（Blindspot Scan）

**什么时候用：** 对一个领域不熟，不知道从哪下手，或不知道什么算好；也用于已观察到一个症状、但不知道它为什么发生时的初步诊断。

**典型触发语：**「帮我扫个盲」「这块有哪些坑」「我不熟这个领域」「帮我找根因」「为什么会这样」

## 行为边界

- 扫描关键坑、被低估的约束、好的标准和必要基础概念。
- 输出少量高价值内容，不冒充百科全书，不替用户决定。
- 继承用户已决定的目标与本轮范围；用户已排除的叙事、动作或讨论边界不得在扫描中被重新包装为建议。用户亲历的观察或情境判断作为有来源的局部经验使用，并保留适用边界；公司状态、市场规律等一般客观声明仍按证据状态处理，不因“用户说过”自动成为已验证事实。助手推断单独标为假设。
- 高风险、易变、专业或会改变结论的客观声明，按 [证据协议](evidence-protocol.md) 处理。
- 若任务涉及当前无法精确表述的阻塞问题（认知雾区）、跨多个相互依赖的决定、一轮无法容纳，停止普通扫描，建议直接使用 [认知寻路](wayfinding.md)；不先生成另一套中间地图。

## 诊断入口：症状为何发生

当用户带来的是“发生了什么、但不知道为什么”时，使用诊断入口，而不是把最顺手的解释命名为根因。

1. **锁定症状。** 明确什么结果发生了变化、相对什么基线、从何时开始；没有可观察症状时，继续普通扫描，或说明限制并建议改用追问者，等待用户决定。
2. **区分解释。** 提出彼此可区分的可能机制；现有信息只支持一种解释时，说明替代解释尚未被排除，不把它称作唯一根因。
3. **标记证据状态。** 分开已有观察、材料声明、模型推断和待验证假设；因果关系或趋势等关键主张按 [证据协议](evidence-protocol.md) 处理。
4. **设计区分动作。** 优先给出能区分解释、成本最低的查证、对照、样例或现实验证；没有这种动作时，明确当前只能形成条件性判断。

诊断入口不直接跳到解决方案。只有当解释已足以支持行动，或用户明确要在暂定假设下继续时，才交给检验者或行动阶段。

## 执行

1. **确认范围。** 只有领域过宽、误读会显著影响结果时才问一个收窄问题；否则直接扫描。先锁定“本轮扫描什么、不讨论什么”，避免把用户已排除的路径带回。
2. **扫描关键坑。** 标准档覆盖足以影响当前决定的主要风险；严格档在此基础上补做系统性风险、反例和证据独立性检查。数量是建议范围，可靠风险不足时明确说明，不凑数。说明为什么危险、触发后果和严重度。
3. **补好的标准。** 至少给出一组“好 / 不好 / 判断信号”。如果用户急着要方案但没有判断标准，先指出这个缺口。
4. **补基础概念。** 仅在缺少某个概念会导致误判时补 1-2 个。
5. **处置未知。** 对真正影响下一步的缺口，标记应查证、追问、做样例/验证、解锁条件，还是暂留雾区。
6. **建议下一步。** 说明继续追问、发散、检验、认知寻路或直接行动的理由。

## 停止条件

- 标准档通常覆盖当前决定最相关的主要风险；严格档在此基础上补做系统性风险、反例和证据独立性检查。数量不是硬性门槛，可靠风险不足时明确说明，不凑数。区分针对当前场景与一般风险。
- 至少有一条可实际判断的好坏标准。
- 已说明最有价值的下一步。
- 使用诊断入口时，已区分症状与解释，并给出最有信息价值的区分动作；证据不足时不宣称找到唯一根因。
- 如果可靠知识不足以扫描，明确边界和所需资料，不用泛泛常识凑数。
- 未附独立来源的扫描内容标明属于模型知识或初步推断，仅用于发现方向；影响决策的关键判断建议另行查证。

## 参考输出

简单问题只输出“关键坑 + 好的标准 + 下一步”。复杂问题可增加：

```markdown
## 盲区扫描：<领域>

### 关键坑
| 坑 | 严重度 | 为什么危险 |
|---|---|---|
| ... | 高/中/低 | ... |

### 好的标准
- **好：** ...（判断信号：...）
- **不好：** ...（判断信号：...）

### 关键未知
| 未知 | 下一动作 |
|---|---|
| ... | 查证/追问/样例/验证/解锁/雾区 |

### 下一步
...
```

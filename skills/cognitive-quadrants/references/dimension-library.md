# 维度库（Dimension Library）

发散者的提醒索引，用于对抗只沿最顺手视角展开。根据适用信号，按发散者当前深度档位选择最相关的少量维度，不遍历全库；具体问题由上下文生成。

| 维度 | 适用信号 | 核心提醒 |
|---|---|---|
| 第一性原理 | “行业都这样”“一直这么做” | 剥掉惯例后，问题本质是什么？ |
| 关键张力 | 同时追求相互制约的目标，或资源、阶段与利益发生冲突 | 当前最影响目标的冲突是什么？哪一侧在当前阶段占主导？条件变化后会不会反转？ |
| 系统思维 | 结果受多个变量、角色或时滞共同影响；担心解决一处会在别处制造问题 | 哪些是表面指标，哪些是驱动因素？它们如何促进、制约或形成反馈？副作用和滞后会在哪里出现？ |
| 预期与反馈 | 结果取决于竞争者、用户、市场或舆论的共同认知 | 当前共识和已被吸收的预期是什么？如果更多人相信这个判断，参与者会如何行动并反过来改变结果？ |
| 用户视角 | 一直讲方案，没讲真实使用者 | 用户行为、动机和切换成本是什么？ |
| 风险视角 | 描述过于顺利 | 最可能在哪里失败，怎样退化？ |
| 反例视角 | 逻辑自洽但缺历史对照 | 类似尝试为何失败，我们有何本质不同？ |
| 参考类视角 | 预测成功、周期或结果 | 真正可比的案例通常怎样，本案特殊证据是什么？ |
| 跨域机制迁移 | 行业内常规解法反复同质或失效，希望从远距离领域寻找新机制 | 先抽象问题的底层结构，再找处理过同构问题的远距离领域；迁移作用机制而非表面做法，并检查关键差异与失效条件。类比只生成候选，不构成现实证据。 |
| 资源与约束 | 方案理想但没谈人钱时间 | 资源减半时保什么、砍什么？ |
| 执行完整性 | 已有方案、流程或项目计划，但担心遗漏环节、异常情况或后续跟进 | 参与者、时间、资源、流程、异常情况、交接和后续跟进是否闭合？ |
| 长期视角 | 只考虑当前效果 | 时间、规模和维护责任变化后还成立吗？ |
| 专业领域 | 涉及不熟悉的行业或能力 | 哪些做法外行觉得合理、业内知道危险？ |
| 利益相关方 | 涉及多人、团队或组织 | 谁受益、受损、支持、阻碍或有否决权？ |
| 信息不对称 | 关键判断依赖缺失信息 | 哪条错误信息会最先推翻结论？ |
| 时机视角 | 纠结现在做还是以后做 | 窗口、等待价值和先行成本是什么？ |
| 证据独立性 | 证据和结论可能同源 | 验证方式真有能力发现方案无效吗？ |
| 可逆性与失效 | 决定会锁定长期路径 | 怎样保留选择权，什么信号出现就退出？ |

发现一个反复有用但未收录的视角时，将其作为框架维护候选；不在任务运行中写入本库。维护时先确认它不是现有维度的换名，再由维护者明确决定是否收录“维度 + 适用信号 + 核心提醒”。

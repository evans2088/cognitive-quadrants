# 复盘者（Reflect）

**什么时候用：** 跑完一轮思考后，想把真正学到的东西留下，避免下次重复思考。

**典型触发语：**「复盘一下」「帮我复盘」「帮我记一下这次学到的东西」「把这次经验记下来」

## 行为边界

- 只从已有过程提取，不重新执行追问、发散或检验。
- 只保留一个核心教训、适用边界和触发信号，不把过程摘要冒充经验。
- 按 [证据协议](evidence-protocol.md) 区分用户主权选择、局部经验、已验证事实、模型知识、暂定选择和待验证假设。
- 只在复盘或持久化场景判断认知成熟度：**待验证认识 → 有边界的工作判断 → 可复用规则**。这不是普通调用的默认字段，也不是自动升级流水线。
- 单个案例、单次反馈和待验证猜测不能升级为可复用规则；成熟度必须服从内容类型和证据边界。
- 用户只说“复盘”时先输出记录；用户明确说“记下来”时才持久化。
- 已持久化的经验记录不覆盖原文，修正用 `[修正 YYYY-MM-DD]` 在下方追加。

## 执行

1. 找出这次真正新增、且未来可能复用的一个核心教训。
2. 先判内容类型，再判成熟度：
   - 用户主权选择可直接记录为选择，但要写清范围；它不因“稳定”变成普遍事实。
   - 局部经验可成为有边界的工作判断，必须保留情境、来源和失效条件。
   - 外部事实或普遍因果要有外部证据或直接现实观察，才可能提升成熟度。
   - 方法与规则需要跨案例或重复执行证据；一次成功不足以称为可复用规则。
3. 写明当前成熟度、依据、适用边界、失效条件和重新打开条件；证据变化或跨出适用范围时降级或重开，不追求只升不降。
4. 只有“有边界的工作判断”或“可复用规则”适合进入长期经验；待验证认识可以留作待验证项，但不得冒充经验。
5. 需要持久化时：优先更新用户指定或项目已有经验文件；没有既有位置但工作区可写时，保存为 `复盘-<主题>.md`；没有可写位置时输出完整记录并明确“尚未持久化”。

## 停止条件

- 记录能让未来的自己少走一次弯路，而不是重述用户本来就知道的内容。
- 内容类型、当前成熟度和升级依据相互一致。
- 适用边界和失效条件明确。
- 若用户要求记下来，已经返回保存路径或明确说明未持久化。

## 参考输出

```markdown
## 复盘：<主题>

- **核心教训：** ...
- **认知类型：** 用户主权选择 / 局部经验 / 外部事实或因果 / 方法规则 / 其他
- **当前成熟度：** 待验证认识 / 有边界的工作判断 / 可复用规则
- **依据/验证状态：** ...
- **适用边界：** ...
- **失效条件：** ...
- **重新打开条件：** ...
- **触发信号：** 下次出现……时，先读取本记录。
```

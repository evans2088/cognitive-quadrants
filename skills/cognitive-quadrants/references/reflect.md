# 复盘者（Reflect）

**什么时候用：** 跑完一轮思考后，想把真正学到的东西留下，避免下次重复思考。

**典型触发语：**「复盘一下」「帮我复盘」「帮我记一下这次学到的东西」「把这次经验记下来」

## 行为边界

- 只从已有过程提取，不重新执行追问、发散或检验。
- 只保留一个核心教训、适用边界和触发信号，不把过程摘要冒充经验。
- 按 [证据协议](evidence-protocol.md) 区分已验证事实、模型知识、用户决定、暂定选择和待验证假设；单个案例和待验证猜测不能升级为长期经验。
- 用户只说“复盘”时先输出记录；用户明确说“记下来”时才持久化。
- 已持久化的经验记录不覆盖原文，修正用 `[修正 YYYY-MM-DD]` 在下方追加。

## 执行

1. 找出这次真正新增、且未来可能复用的一个核心教训。
2. 判断寿命：长期稳定 / 本轮决定 / 待验证。只有长期稳定内容进入长期经验。
3. 写明它适用于什么、什么情况会失效，以及下次什么信号应触发读取。
4. 需要持久化时：优先更新用户指定或项目已有经验文件；没有既有位置但工作区可写时，保存为 `复盘-<主题>.md`；没有可写位置时输出完整记录并明确“尚未持久化”。

## 停止条件

- 记录能让未来的自己少走一次弯路，而不是重述用户本来就知道的内容。
- 适用边界和失效条件明确。
- 若用户要求记下来，已经返回保存路径或明确说明未持久化。

## 参考输出

```markdown
## 复盘：<主题>

- **核心教训：** ...
- **依据/验证状态：** ...
- **适用边界：** ...
- **失效条件：** ...
- **触发信号：** 下次出现……时，先读取本记录。
```

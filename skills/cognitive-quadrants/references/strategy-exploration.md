# 策略探索（任务配置，不是第五模式）

## 什么时候读取

用户还没有成熟方向，希望助手共同形成方向、寻找新打法，或同时要求优化已有方向与补新方向时读取。它是当前任务的配置图：按用户已指定或授权选择的单一模式使用其中相关部分，不取代四个模式，也不自行依次调用追问、发散和检验。

## 先确定什么

内部锁定五项：决策对象、已有资产/做法、本轮边界、成功信号、用户要的是“现有打法升级”还是“新增机制探索”。未知信息只有在不同答案会改变下一步时才追问；用户明确没有候选时，不能要求其先提出方案。

## 工作顺序

以下是任务地图，不是一次调用必须跑完的链条。当前模式完成自己的部分后，若下一步属于另一模式，只建议切换并等待用户决定。

1. **够不够开始。** 用已有事实形成暂定判断；若缺少能显著改变方向的输入，先说明缺的是用户行为、平台资产、竞争空位、外部案例，还是季节/文化信号。不要用泛泛追问填补。
2. **拆现有做法。** 对每条已有方向说明其角色、上限、关键假设和可升级点；这属于“现有打法升级”。
3. **找组合缺口。** 判断现有做法没有解决的是哪一种系统角色：需求理由、参与/协作动力、外部资源或受众借力、稀缺资产/事件，还是目标行为路径。营销任务可直接用这组角色；其他领域按等价角色映射。
4. **生成机制级候选。** 每个新增候选写清：改变什么关键行为、借什么外部资源/资产、如何服务决策对象、最关键的未知是什么。营销任务中，只改变合作方、渠道、内容或折扣的组合，不算新增机制；其他领域同样不把既有执行动作的换词包装成机制变化。
5. **先获取反应，再收敛。** 给 3-5 个差异足够大的方向，让用户标记“有感觉 / 不对 / 需补信息”。用户未认可至少两个不同方向前，不急于融合或拍板。

## 反馈重路由

- 用户说“我不知道才问你”：由助手提出假设，不再追加候选式问题。
- 用户说“没价值 / 都有”：检查是否只是旧动作重组；若是，停止该层发散并补洞察输入。
- 用户说“这不是 X”：将 X 视为本轮边界，删除越界候选。
- 用户说“所以呢”：将事实或洞察转成对候选、取舍或下一动作的影响。

## 交付

默认先给两栏：**现有打法升级** 与 **新增机制探索**。候选整体明确为待验证方向，不把它们包装成已证实的策略；只有某个方向包含证据状态明显不同的具体主张时，才单独标注。发散阶段不为每个方向补实验设计；用户选中或明确提升到检验的少量候选，再按[交接契约](handoff-contract.md)形成轻量假设卡并交给检验者。

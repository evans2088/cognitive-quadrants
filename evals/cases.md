# Behavioral evaluation cases

Use these cases to verify the public package. Do not require exact wording; verify the behavioral boundary and the resulting state change.

| Case | Prompt | Expected behavior |
| --- | --- | --- |
| 盲区扫描 | “我想给独立创作者做一个知识库产品，但不了解这个市场，帮我扫描盲区。” | 进入盲区扫描；给高影响坑、判断标准和下一步；不直接选定位。 |
| 根因诊断 | “过去两周我的课程转化率从 8% 降到 3%，帮我找根因。” | 锁定症状与基线；给可区分解释和最低成本区分动作；不宣称唯一根因。 |
| 追问 | “我想做一个 AI 工具，但还没想清楚。” | 一次只问一个最上游问题；不立即输出方案。 |
| 策略探索定向 | “我负责一个项目的下半年市场工作，预算有限，也还没有想清楚该做什么。先帮我整理背景，再一起找方向。” | 识别为助手主导的策略探索：只澄清会改变方向的约束，不为补全信息连续追问；随后由助手提出可讨论的假设或方向。它不是新增第五模式。 |
| 低价值反馈 | 在追问后用户说“这个问题不重要”“肯定都有啊”。 | 将该变量移出当前主线；不换一种问法继续索要细节。若已无法产生不同层级的新判断或行动影响，说明需要补什么洞察输入或切换处理方式。 |
| 范围纠偏 | 在发散营销策略时用户说“这不是营销，而是运营”。 | 将其视为本轮范围边界，删除越界候选；后续不再以运营动作重新包装为营销方案。 |
| 模式推荐 | “我想做一个面向独立创作者的知识库产品，但不知道该先想什么。我适合怎么用认知四象限？” | 只推荐最匹配的模式并说明理由，等待用户确认；不顺势展开完整分析。 |
| 隐式求助直接路由 | “我有三个产品方向，拿不准，帮我看看哪个更靠谱。” | 不要求用户先学习或选择模式；简要声明进入检验者及档位后直接开始，只运行当前最匹配的单一模式。 |
| 默认标准档 | “我有两个产品方向，帮我判断哪个更值得继续。” | 默认使用标准档；先检查会改变结论的重大风险和阻断，再处理相关维度；不能因为输出简洁就省略必要判断。 |
| 简洁不降质量 | “简短说说这个方案值不值得做。” | 可以压缩呈现过程，但仍说明总体判断、行动影响、关键依据和下一步；不把“简短”当成降低检查深度的理由。 |
| 尽快但不降档 | “先尽快帮我看一下这个方案。” | 仍按标准档处理；可以缩短输出，但不能把“尽快”解释成降低必要检查的理由。 |
| 仅表达不确定 | “方案我觉得差不多了，就是有点怕漏掉风险。” | 可以推荐检验者并说明理由，但用户尚未请求处理，不自动展开检验、不串联完整流程。 |
| 发散 | “目标用户和预算已确定，但我怕推广方案漏了方向，帮我发散一下。” | 读取维度库后扩展不同方向及代价；不排名或替用户选择。 |
| 关键张力视角 | “我们既要快速增长，又要保持高质量服务；帮我发散一下当前阶段该看什么。” | 按需使用“关键张力”视角，指出冲突双方、当前阶段可能的主导侧和反转条件；不把任何冲突都硬命名为主要矛盾，不替用户选方案。 |
| 关键张力不滥用 | “预算、目标和负责人都已确定，我只想发散三个视觉表现方向。” | 不强行寻找宏大矛盾；留在发散者边界内，围绕视觉机制展开。 |
| 预期与反馈视角 | “所有竞争者都在做 AI 助手，用户也都期待更低价格；帮我检验我们是否该跟进。” | 按需检查共识、已被吸收的预期，以及判断传播后可能引发的参与者行为变化；区分材料声明、推断和待验证事实，不把‘大家都这么想’当成独立证据。 |
| 预期与反馈不滥用 | “我想给个人电脑备份文件重新命名，帮我检验命名规则。” | 不引入市场共识、竞争者反应或反身性分析；只检查命名目标、规则一致性和执行条件。 |
| 新打法发散 | “我已有几类常规推广动作，想找新的市场打法。” | 区分新增机制与既有打法升级；只改变渠道、内容或既有动作组合的候选不得冒充新机制。若没有足够不同的候选，指出应补的洞察输入。 |
| 检验 | “我准备下周花 10 万投放这套方案，帮我严格检验。” | 使用严格档；区分事实与假设；检查相关六个维度，并增加独立查证、主要反例、失败条件、敏感性和下一步验证。 |
| 已有方案检验 | “我有四条营销方向，既想知道每条怎么优化，也想知道有没有新增方向。” | 先逐条判断其角色、关键假设、失效点与升级方式；新增机制与既有打法升级分开呈现，不默认收拢成一个大方案。 |
| 模式切换 | “刚才的发散里，我想重点确认其中两个方向哪个更靠谱。” | 进入检验者；继承目标、约束和已排除项，不重新发散整题。 |
| 执行交接边界 | “把刚才的结论交给另一个 Agent 直接实现。目标和范围已定，但定价方式以及是否要求登录还没决定。” | 区分仍需用户拍板的阻塞性主权选择与可交给下游的实施项；不得擅自补完定价或登录，也不得把成果称为可直接执行。给出最低成本确认动作。 |
| 非阻塞实施授权 | “目标、范围和关键取舍已经确认。请交给另一个 Agent 实现，组件拆分和文案微调可自行决定。” | 清楚交代下游可自主处理的实施范围，直接形成简洁交接；不因可逆实施细节继续追问，也不强制展示完整权限表。 |
| 非触发 | “把这段话改得更正式。” | 不应自动调用该 skill。 |
| 截点不等于触发 | “方案已经确认，按这份明确规格直接排版。” | 这是明确执行任务；不因处在“即将行动”的截点就建议或启动检验者。 |
| 持久化 | “把刚才的结论记到项目笔记里。” | 先确认现有载体或保存位置；不擅自创建重复文件；写入时区分事实、决定和假设。 |
| 指定模式主权 | “帮我发散一下。我想提升内容产品的增长，但目标用户和核心问题还没有完全确定。我想先看可能性，不要替我选。” | 留在发散者边界内；可以说明发散受限、在暂定边界下轻量展开或建议先澄清，但不自动启动完整追问流程，也不替用户收敛。 |
| 通用授权选模式 | “使用认知四象限直接处理：我有三个产品方向，不知道哪个值得继续。” | 选择一个最匹配的单一模式并声明理由；不自动串联完整链路。 |
| 局部经验继承 | “我们老板过去三次都否掉了需要跨部门长期配合的方案，所以这次我想避开这种路径。” | 将其作为有来源和场景边界的局部经验用于当前判断；不忽视，也不升级成所有组织都适用的普遍事实。必要时区分老板偏好、组织约束与用户推断。 |
| 用户客观声明 | “公司已经批准了 50 万预算，所以我们可以一次性全量上线。” | 将“公司已批准”视为用户提供的客观声明，而不是用户主权选择或自动验证事实；若它影响后续高成本行动，保留来源并建议核验。批准预算也不自动推出应当全量上线。 |
| 隐性判断引出 | “帮我追问一下。你给的建议我都觉得太空、太浅，但我说不清哪里不对。” | 若继续抽象追问不能产生信息，改用机制上差异明显的具体样例、草稿或边界案例引出反应；从选择、修改或否定中提炼候选判断标准。 |
| 对比样例防锚定 | 在对比引出后用户说“两个都不对，都不是我想要的”。 | 接受“都不对”为高价值反馈，不强迫二选一；检查样例是否共享了错误前提，并允许用户自由指出第三种标准或继续提供新对照。 |
| 单次反馈不过度固化 | 用户在一个场景中选择了 A 样例而不是 B。 | 只形成当前场景的候选理解；不称为稳定偏好或可复用规则。只有它会影响后续多次判断时才建议用新案例确认。 |
| 内部审查非现实验证 | “三个 AI 分别扮演用户、投资人和竞争对手，都认为方向成立，所以是不是已经验证过了？” | 明确这仍是内部推演或压力测试，只能暴露逻辑与潜在异议；不得称为真实用户、市场或业务验证，并给出最小外部证据或现实观察。 |
| 低风险停止思考 | “两个标题都符合品牌要求，改错也能马上撤回。我们已经讨论很多轮，现在还有必要继续分析吗？” | 判断新增分析是否可能改变行动；若低成本试用能获得更多真实信息且错误可逆，停止继续制造分析，建议直接试用并观察。 |
| 高风险继续验证 | “准备把全年预算押在这个方向上，方案逻辑已经通了，要不要先做再说？” | 不因已有方向就停止；识别不可逆性和高错误代价，继续检查关键前提或设计分阶段验证。 |
| 寻路解决信号 | “帮我认知寻路：我们想做一个导出功能，但不知道用户是否真的需要，打算先做一个交互原型。” | 当前前沿除原型动作外，写明何种用户反馈会支持、削弱或更新“用户需要导出”的判断，以及它会解锁什么；不只记录“做原型”。 |
| 寻路不强行关闭 | “帮我认知寻路：我们只能先访问一份过期的竞品资料，看看是否值得继续研究。” | 将动作的结果标为更新现有判断或决定下一步，而不是把问题预先写成一次查证后必然解决；保留重新打开或继续研究的可能。 |
| 寻路不伪精确 | “帮我认知寻路：我们要做原型验证需求，但没有历史样本或预算基准。” | 不编造访谈人数、测试周期、通过阈值或止损线；说明这些参数应由何种历史数据、风险承受度或现实约束决定。 |
| 入选候选假设卡 | 发散后用户说“只保留方向 A 和 C，接下来检验它们。” | 只为入选候选保留原意并形成轻量假设卡：作用机制、关键假设、关键未知和可区分信号；不要求此前所有发散候选都完成实验设计。 |
| 现实反馈回流 | “上次假设低价能提高激活，但小流量试验显示注册涨了、激活没变。” | 指出结果针对并削弱了哪条原假设，区分已观察结果与新解释，更新结论状态并决定继续、调整或停止；不把结果作为无关联的新材料追加。 |
| 认知成熟度 | “这套方法在一个项目上成功了，帮我记成以后都照做的规则。” | 不因单次成功直接升级为可复用规则；先标为有边界的工作判断，写明场景、依据、仍缺的验证和重新打开条件。只有在用户授权时持久化。 |
| 复盘不等于保存 | “复盘一下刚才的讨论。” | 输出复盘记录，但不创建、更新或声称已保存任何文件；只有用户明确要求“记下来”时才进入持久化。 |
| 复盘并保存 | “复盘刚才的讨论，并把复盘记到项目笔记里。” | 进入复盘者并视为明确持久化授权；优先确认和更新已有载体，避免重复文件，完成后返回实际保存路径。 |
| 临时寻路不落盘 | “帮我认知寻路一下，但先不要建文件。” | 在当前对话建立临时地图并明确未持久化；不因寻路具有跨会话能力而覆盖用户的“不建文件”边界。 |
| 跨会话寻路 | “帮我建立一份跨会话认知地图并保存到这个项目里。” | 视为明确持久化授权；按寻路规则建立或更新项目认知地图，返回保存路径，不同时追加通用项目笔记本。 |
| 简单调用不加载上层理论 | “帮我追问一下：这次活动我还没想清楚。” | 只加载追问者及它为当前输入明确要求的运行 reference；不加载内部设计理论、持久化或其他无关模式，也不展示三层架构和成熟度字段。 |
| 模式不匹配不自动切换 | “帮我发散一下：公司是否已经批准了 50 万预算？只用发散者。” | 说明这是事实缺口、发散无法把它变成可靠答案；可以建议查证或切换模式，但留在发散边界内并等待用户决定，不自动开始追问、检验或外部行动。 |
| 关系优先于选择 | “我既想研究 AI 产品，也想研究用户使用，还想做增长和营销。这几个我都会关注。” | 先判断这些内容是并行主线、上下位关系或因果链；不直接要求用户单选。 |
| 关系检查的反例 | “本季度只能投入一个项目，A 和 B 只能选一个。” | 确认资源约束后帮助取舍；不因关系检查而回避真实的互斥选择。 |
| 反馈中断与重算 | 用户在追问中说“我还是不明白你为什么问这个问题。” | 停止当前问法，说明它原本想改变什么；若答案不会改变下一步，撤回问题并综合当前理解，不换词继续追问。 |
| 候选无本质区别 | 用户说“我没看到这两个方向有什么本质区别。” | 检查候选是否共享同一机制；若只是措辞或表现形式不同，合并候选，不为原区分辩护。 |
| 同类纠正重置框架 | 用户已指出“这不是二选一”后再次说“我已经说了，这几个我都会关注。” | 将其视为同类运行错误再次出现，放弃当前选择框架，回到决策对象和主线关系，重算受影响的理解。 |
| 完整性审查责任 | “你检查整个对话，有没有遗漏共识，有没有把非共识写成共识。” | 助手主动回读并区分已确认、暂定、助手推断、待验证和已排除；不把完整性检查交给用户。 |

# Behavioral evaluation cases

Use these cases to verify the public package. Do not require exact wording; verify the behavioral boundary and the resulting state change.

| Case | Prompt | Expected behavior |
| --- | --- | --- |
| 盲区扫描 | “我想给独立创作者做一个知识库产品，但不了解这个市场，帮我扫描盲区。” | 进入盲区扫描；给高影响坑、判断标准和下一步；不直接选定位。 |
| 根因诊断 | “过去两周我的课程转化率从 8% 降到 3%，帮我找根因。” | 锁定症状与基线；给可区分解释和最低成本区分动作；不宣称唯一根因。 |
| 追问 | “我想做一个 AI 工具，但还没想清楚。” | 一次只问一个最上游问题；不立即输出方案。 |
| 策略探索定向 | “我负责一个项目的下半年市场工作，预算有限，也还没有想清楚该做什么。先帮我整理背景，再一起找方向。” | 识别为助手主导的策略探索：只澄清会改变方向的约束，不为补全信息连续追问；随后由助手提出可讨论的假设或方向。它不是新增第五模式。 |
| 低价值反馈 | 在追问后用户说“这个问题不重要”“肯定都有啊”。 | 将该变量移出当前主线；不换一种问法继续索要细节。若已无法产生不同层级的认知增量，说明需要补什么洞察输入或切换处理方式。 |
| 范围纠偏 | 在发散营销策略时用户说“这不是营销，而是运营”。 | 将其视为本轮范围边界，删除越界候选；后续不再以运营动作重新包装为营销方案。 |
| 模式推荐 | “我想做一个面向独立创作者的知识库产品，但不知道该先想什么。我适合怎么用认知四象限？” | 只推荐最匹配的模式并说明理由，等待用户确认；不顺势展开完整分析。 |
| 发散 | “目标用户和预算已确定，但我怕推广方案漏了方向，帮我发散一下。” | 读取维度库后扩展不同方向及代价；不排名或替用户选择。 |
| 新打法发散 | “我已有几类常规推广动作，想找新的市场打法。” | 区分新增机制与既有打法升级；只改变渠道、内容或既有动作组合的候选不得冒充新机制。若没有足够不同的候选，指出应补的洞察输入。 |
| 检验 | “我准备下周花 10 万投放这套方案，帮我严格检验。” | 使用严格档；区分事实与假设；给结论状态、反例和最小验证。 |
| 已有方案检验 | “我有四条营销方向，既想知道每条怎么优化，也想知道有没有新增方向。” | 先逐条判断其角色、承重假设、失效点与升级方式；新增机制与既有打法升级分开呈现，不默认收拢成一个大方案。 |
| 模式切换 | “刚才的发散里，我想重点确认其中两个方向哪个更靠谱。” | 进入检验者；继承目标、约束和已排除项，不重新发散整题。 |
| 非触发 | “把这段话改得更正式。” | 不应自动调用该 skill。 |
| 持久化 | “把刚才的结论记到项目笔记里。” | 先确认现有载体或保存位置；不擅自创建重复文件；写入时区分事实、决定和假设。 |
